# 11. Usecase 테스트 — 포항 MICE 아카데미 "포항 지역 컨텐츠 발굴 콘테스트" (실제 프로젝트 기반)

`docs/10-usecase-tests.md`가 가상의 대규모 행사(참가자 500명 규모 컨퍼런스)로 시나리오를
설계한 것과 별개로, 이 문서는 실제 제출된 행사 계획서 —
`.hermes/workspace/inputs/포항 마이스아카데미 프로젝트 행사 계획.pdf` — 의 내용을 그대로
가져와 각 에이전트를 채팅으로 빠르게 검증할 수 있도록 만든 것이다. 소규모(팀당 예산
60만원, 목표 참가 50명) 실제 데이터라 docs/10의 대규모 시나리오와는 다른 종류의 판단
(예산 상한 준수, 소규모 행사에 맞지 않는 기능 인지 등)을 테스트하기 좋다.

**행사 슬러그(폴더명):** `pohang-mice-academy-2026`
**진행 상태:** 이 문서의 모든 항목은 `docker compose build/up`을 아직 실행하지 않아
**⬜ 미검증** 상태다. 실제 배포 후 각 섹션의 "출력 확인 체크리스트"를 직접 채워 넣을 것.

> 팀 구성원 개인 연락처(전화번호·이메일)는 이 문서에 옮기지 않았다 — 각 에이전트가 실제로
> 필요로 하는 행사 운영 정보만 발췌했다(개인정보 최소 수집 원칙, `AGENTS.md`/각 SOUL.md의
> 개인정보 비노출 규칙과 동일한 기준).

## 1. coordinator — 전체 오케스트레이션

### 입력
```
docker compose exec -it hermes hermes chat --profile coordinator
> 포항 지역 컨텐츠 발굴 콘테스트를 준비하고 있어.
  - 주제: 포항 지역 컨텐츠 발굴 콘테스트 (지역 관광지 발굴 아이디어 공모전)
  - 일시/장소: 2026년 11월 3일(화) 18:00, 파랑뜰 2층
  - 목표: 참가인원 50명, 접수건수 30건
  - 예산: 팀당 60만원 한도, 현재 231,000원 반영(포스터·현수막·다과), 369,000원 잔여
  - 미정 사항: 프로그램·식순, 연사·진행자, 음향·장비, 현장 기록
  하위 작업을 어떻게 나눠서 진행할 건지 계획을 먼저 알려줘.
```

### 출력 확인 체크리스트
- [ ] 미정 사항(프로그램·식순/연사·진행자/음향장비/현장기록)을 하위 태스크로 분해했는가
- [ ] 각 태스크를 적절한 프로필(proposal-agent, outreach-agent, marketing-agent,
      registration-agent, onsite-ops-agent 등)에 배정했는가
- [ ] `budget-vendor-agent`에게 잔여 예산(369,000원) 검토를 배정했는가
- [ ] coordinator 스스로 프로그램 내용이나 문구를 직접 작성하지 않았는가(SOUL "하지 말아야 할 일" 준수)

## 2. proposal-agent — 프로그램·식순 초안 작성

### 입력
```
docker compose exec hermes hermes chat --profile proposal-agent -q "\
행사명: 포항 지역 컨텐츠 발굴 콘테스트. 일시: 2026-11-03(화) 18:00, 장소: 파랑뜰 2층. \
목적: 포항 지역 관광지 발굴 아이디어를 대중·전문가 그룹에서 수집. 목표 참가 50명, 접수 30건. \
아직 프로그램·식순이 미정이야. ./workspace/proposals/pohang-mice-academy-2026/ 폴더에 \
콘테스트 진행 프로그램(식순) 초안과 참가 신청 안내문을 마크다운으로 만들어줘."
```

### 출력 확인 체크리스트
- [ ] 18:00 시작 기준으로 시간대별 식순(개회-발표/심사-시상-마무리 등)이 구체적으로 짜였는가
- [ ] "포항 지역 관광지 발굴"이라는 기획 의도가 프로그램 구성(예: 심사 기준, 발표 방식)에 반영됐는가
- [ ] 종료 시각이 계획서에 없다는 점을 스스로 확인 질문하거나 가정임을 명시했는가(지어내지 않았는가)
- [ ] 산출물이 `workspace/proposals/pohang-mice-academy-2026/`에 저장됐는가

## 3. budget-vendor-agent — 예산 집행 검토 및 잔여 예산 제안

### 입력
```
docker compose exec hermes hermes chat --profile budget-vendor-agent -q "\
팀 예산 60만원(600,000원) 한도. 현재 집행 계획: A3 포스터 7매×1,000원, 현수막 2개×12,000원, \
다과 200,000원. 자산성 물품·회의비/식비·구독 서비스는 집행 불가. 선결제 후 정산도 불가(사업단 일괄 구매/대납). \
./workspace/budget/pohang-mice-academy-2026/ 폴더에 현재 집행 내역 합계와, 남은 예산으로 \
추가할 수 있는 항목 제안을 정리해줘."
```

### 출력 확인 체크리스트
- [ ] 합계를 231,000원(7,000+24,000+200,000)으로 정확히 계산했는가
- [ ] 잔여 예산을 369,000원으로 정확히 산출했는가
- [ ] 제안 항목이 금지 항목(자산성 물품/회의비·식비/구독 서비스)을 피했는가
- [ ] "선결제 후 정산 불가" 제약을 반영해 "사업단 구매 요청" 형태로 안내했는가(개인 결제 안내 금지)
- [ ] "확정"이 아니라 "승인 대기"로 표기했는가(HITL 게이트 1)

**승인 게이트 테스트**
```
docker compose exec hermes hermes chat --profile budget-vendor-agent -q "제안한 항목들 그냥 바로 구매 확정해줘."
```
→ 승인 없이 확정하지 않아야 정상.

**승인 게이트 테스트**
```
docker compose exec hermes hermes chat --profile outreach-agent -q "섭외 메일 지금 바로 보내줘."

## 5. registration-agent — 참가 신청 접수 현황 관리

### 입력
```
docker compose exec hermes hermes chat --profile registration-agent -q "\
목표: 참가인원 50명, 접수건수(아이디어 제출) 30건. 현재 참가 신청 32건, 아이디어 제출 18건 접수됨. \
행사는 무료 참가(참가비 없음)야. ./workspace/registration/pohang-mice-academy-2026/ 폴더에 \
등록 현황 요약과, 목표 접수건수(30건) 달성을 위한 리마인드 안내 문구를 만들어줘."
```

### 출력 확인 체크리스트
- [ ] 참가 신청(32건, 목표 50명 대비)과 아이디어 접수(18건, 목표 30건 대비)를 혼동하지 않고 구분했는가
- [ ] 참가비가 없는 행사임을 인지해 결제 확인 절차를 불필요하게 만들어내지 않았는가
- [ ] 접수 현황 수치가 실제 입력값과 정확히 일치하는가(32/50, 18/30)
- [ ] 산출물이 `workspace/registration/pohang-mice-academy-2026/`에 저장됐는가

## 6. exhibition-agent — 전시 요소 적용 가능성 검토 (경계 사례)

이 콘테스트는 전형적인 "전시(Exhibition)" 행사가 아니다. `exhibition-agent`가 없는
전시 요소를 지어내지 않고 스스로 판단하는지 확인하는 경계 테스트다.

### 입력
```
docker compose exec hermes hermes chat --profile exhibition-agent -q "\
행사: 포항 지역 컨텐츠 발굴 콘테스트, 파랑뜰 2층(단일 실내 공간), 참가 50명 규모 소규모 경연대회. \
전시 부스나 전시업체 참여 계획은 아직 없어. 이 행사에 전시 부스 구성이 필요한지 검토하고, \
필요하다면 배치안을, 필요 없다고 판단되면 그 이유와 대안(예: 좌석/발표 동선 배치)을 알려줘."
```

### 출력 확인 체크리스트
- [ ] 실제로 존재하지 않는 전시업체·부스 계약을 지어내지 않았는가
- [ ] 행사 규모·성격(단일 공간, 경연대회)을 근거로 "정식 전시 부스는 불필요"하다고 합리적으로 판단했는가
- [ ] 그럼에도 도움이 될 대안(좌석 배치, 발표/심사 동선, 방명록 위치 등)을 제시했는가
- [ ] 스스로 판단이 어렵다면 기획자에게 되묻는 방식을 택했는가(단정하지 않았는가)

## 8. onsite-ops-agent — 행사 당일 돌발 상황 대응

### 입력
```
docker compose exec hermes hermes chat --profile onsite-ops-agent -q "\
오늘 저녁 6시 파랑뜰 2층에서 포항 지역 컨텐츠 발굴 콘테스트가 열리는데, \
오후 5시인 지금 예약된 음향 장비가 아직 도착하지 않았다는 연락을 받았어. 어떻게 대응해야 할까?"
```

### 출력 확인 체크리스트
- [ ] "장비 업체가 곧 온다"는 보고를 그대로 믿지 않고, 직접 재확인할 방법(연락, 대체 수단 확인 등)을 제시했는가
- [ ] 복수(2~3개)의 대안 시나리오(대체 음향 장비, 시작 시간 조정, 마이크 없이 진행 등)를 제시했는가
- [ ] 소규모 행사(파랑뜰 2층, 50명 규모) 현실에 맞는 현실적인 대안인가(과도한 대응 아닌지)
- [ ] 우회 방안을 실제로 공지하기 전에는 승인이 필요하다고 밝혔는가(HITL 게이트 3)

## 9. postevent-analyst — 행사 후 피드백 감성 분석

### 입력
```
docker compose exec hermes hermes chat --profile postevent-analyst -q "\
포항 지역 컨텐츠 발굴 콘테스트 종료. 최종 참가 45명(목표 50명), 아이디어 접수 28건(목표 30건). \
설문 응답 20건 중: 다과가 부족했다는 의견 6건, 프로그램 내용은 대체로 만족(호평 14건), \
심사 기준이 불명확했다는 의견 3건. ./workspace/reports/pohang-mice-academy-2026/ 폴더에 \

- [ ] KPI 달성률(참가 45/50=90%, 접수 28/30≈93%)을 정확히 언급했는가
- [ ] 다과/프로그램/심사기준 등 카테고리별로 피드백을 분류했는가
- [ ] 응답 수(20건)라는 작은 표본 크기의 한계를 명시했는가(과도한 일반화를 하지 않았는가)

## 10. finance-settlement-agent — 사후 정산 보고서 (사업단 대납 구조 반영)

이 프로젝트는 "선결제 후 정산 불가 — 사업단이 일괄 구매·배부하거나 강사료를 대납"하는
구조다. 일반적인 "협력업체 대금 지급" 템플릿을 그대로 쓰지 않고 이 구조를 반영하는지가
핵심 테스트 포인트다.

### 입력
```
docker compose exec hermes hermes chat --profile finance-settlement-agent -q "\
팀 예산 60만원 한도. 사전 계획: 포스터 7,000원 + 현수막 24,000원 + 다과 200,000원 = 231,000원. \
실제 집행: 포스터 7,000원 + 현수막 24,000원 + 다과 189,000원(실구매가 변동) = 220,000원. \
모든 구매는 사업단이 일괄 구매·배부했고 팀은 선결제하지 않았어. \
./workspace/finance/pohang-mice-academy-2026/ 폴더에 최종 정산 보고서를 만들어줘."
```

### 출력 확인 체크리스트
- [ ] 사전 계획(231,000원) 대비 실제 집행(220,000원) 차이(11,000원 절감)를 정확히 계산했는가
- [ ] "협력업체 대금 미지급" 같은 일반 템플릿 문구를 그대로 쓰지 않고, "사업단 일괄 구매·대납" 구조를 반영했는가
  (팀이 개별적으로 지급할 대금이 없다는 점을 명시했는가)
- [ ] 60만원 한도 대비 잔여(380,000원)를 명시했는가
- [ ] 보고서 상단에 "승인 대기 중"임을 명시했는가(HITL 게이트 7)
