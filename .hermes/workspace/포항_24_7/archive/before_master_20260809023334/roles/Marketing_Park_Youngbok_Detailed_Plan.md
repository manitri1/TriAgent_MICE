권장 원칙 (빠르게 결정을 권장)
- 빠른 론칭 우선: 기능은 ‘필수(접수·정보표시)’ vs ‘선택(블로그·심층소개)’로 나눕니다.
- 기술적 난이도 낮추기: 파일 업로드가 필요 없으면 Google Forms 임베드로 바로 론칭. 업로드 필요하면 Netlify Forms / Firebase(또는 간단한 서버) 활용.
- 추적·분석: Google Analytics / GTM + UTM 캠페인 규칙을 표준화.

A. 사이트 개발 — 목적 및 산출물
- 목적: 홍보(포스터·SNS→사이트 유입) 및 접수(폼/파일 업로드/결과 확인) 일원화
- 최소 산출물
  1. 도메인(예: pohang-mice.kr 또는 서브 도메인) 및 SSL 설정
  2. 랜딩(헤드라인, 일시/장소/CTA), 프로그램 요약, FAQ, 심사 기준(요약), 문의 연락처
  3. 접수 폼(직접 개발 또는 Google Forms 임베드) — 파일 업로드 요건 포함시 업로드 처리 방법
  4. 메타 태그(OG/Twitter Card), 공유용 이미지, QR 코드(짧은 URL)
  5. 분석(구글애널리틱스) 및 UTM 템플릿
  6. 배포(스테이징 URL + 최종 URL)

B. 기술 옵션(장단점·권장)
- 옵션 A (권장 — 간편/빠름): 정적 사이트 + Google Forms 임베드
  - 장점: 개발·보안·호스팅 부담 최소, 빠른 론칭, 파일 업로드 불필요 시 최선
  - 단점: 커스텀 파일 업로드·결제 불가
- 옵션 B: 정적 사이트 + Netlify Forms / Formspree + S3/Firebase 업로드
  - 장점: 파일 업로드 가능, 정적 호스팅의 편의성 유지
  - 단점: 약간의 개발·설정 필요, 업로드 정책·용량 관리 필요
- 옵션 C (커스텀 백엔드): Node/Django + DB + 파일 스토리지
  - 장점: 완전한 커스터마이징(로그인·대시보드 등)
  - 단점: 개발·유지비·보안 부담 큼 — 행사 성격상 권장하지 않음

권장 선택: 옵션 A(빠른 론칭) 또는 옵션 B(파일 업로드 필요 시)
